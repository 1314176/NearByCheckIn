# 百度地图接管当前分屏窗格设计

## 问题

NearbyCheckIn 启动高德相邻窗格后，系统已经形成“NearbyCheckIn + 高德”的分屏结构。随后直接启动百度地图时未使用独立任务接管标记，百度没有替换 NearbyCheckIn 所在窗格，最终诊断只能识别高德窗口。

## 目标

- 用户启动双地图后，最终窗口必须为“百度地图 + 高德地图”。
- 百度只接管 NearbyCheckIn 所在窗格，不再创建第三个相邻窗格。
- 不改变双地图退到后台后的任务保留行为。
- 不修改打卡命令、窗口诊断和巡航逻辑。

## 设计

新增一个纯 Kotlin 启动标记策略，明确区分两种启动语义：

- 高德相邻窗格：继续使用 `NEW_TASK + LAUNCH_ADJACENT`。
- 百度当前窗格接管：使用 `NEW_TASK + REORDER_TO_FRONT`，不使用 `LAUNCH_ADJACENT` 或 `MULTIPLE_TASK`。

`MainActivity` 通过该策略配置百度启动 Intent。独立任务标记让系统把百度任务带入当前分屏阶段，重排标记优先复用已有百度任务；不添加相邻标记可避免百度占用高德窗格或产生额外窗格。

## 错误处理

百度未安装或启动抛出运行时异常时，沿用现有状态提示并清理待替换状态，不进行循环重启。

## 验证

1. 单元测试验证百度接管标记包含 `NEW_TASK`、`REORDER_TO_FRONT`，且不包含 `LAUNCH_ADJACENT`、`MULTIPLE_TASK`。
2. 运行现有单元测试与 Debug 构建。
3. 安装到设备后启动双地图，检查系统任务栈中同一分屏根任务分别承载百度和高德。
4. 检查无障碍诊断最终显示百度和高德均为 `true`。
