# 百度语义边界手势回退设计

## 1. 背景与结论

小米 14 真机上的百度地图 `21.18.50` 首页能够识别出“首页”和“我的”文本节点，但两个节点均不具备 `ACTION_CLICK`，节点自身不可点击，向上二十层也不存在可执行祖先。

因此，现有“标签节点或最多六层可执行祖先”的点击方式无法进入百度“我的”页面。继续扩大祖先搜索深度不能解决问题，也不能使用固定屏幕坐标或页面位置猜测点击。

本设计在保留 UI Profile 决策、事务调度和重试规则的前提下，为百度地图增加受限的语义边界手势回退。

## 2. 目标

- 百度 Profile 选中明确动作标签后，优先执行现有节点点击。
- 节点点击不可用时，允许使用唯一匹配节点的运行时屏幕边界中心执行一次手势点击。
- 手势目标必须来自当前目标地图窗口中的语义标签节点，不保存或写死屏幕坐标。
- 标签匹配、边界或窗口校验失败时关闭回退，不执行猜测点击。
- 高德地图继续使用现有节点点击路径，不受本次改动影响。
- 无障碍服务正常升级和应用启动时不重复引导用户开启；重新安装后仍遵循系统要求，由用户手动启用一次。

## 3. 方案选择

采用“百度专属的语义边界手势回退”：

1. Adapter 根据 Profile 返回的 `MapUiAction` 取得当前版本允许的标签。
2. 执行器优先查找当前节点或受限祖先并调用 `ACTION_CLICK`。
3. 找不到可执行节点时，只允许唯一匹配、已启用、用户可见且边界有效的标签节点进入手势回退。
4. 手势目标为该节点实时 `boundsInScreen` 的中心点。
5. 由无障碍服务分发一次短时点击手势；提交失败时返回明确失败结果。

不采用以下方案：

- 固定绝对坐标或屏幕比例坐标：无法证明目标仍是 Profile 选中的语义节点。
- 无视节点动作能力强制调用 `ACTION_CLICK`：真机诊断已经证明节点未声明点击能力，不能形成可靠闭环。
- 扩大祖先深度：真机二十层诊断未发现可执行祖先。

## 4. 架构与职责

### 4.1 Profile

`BaiduUiProfile` 继续只负责页面分类和下一动作决策，不接触 Android 类型、节点边界或手势 API。

百度页面快照只在以下条件全部满足时，才把白名单标签节点表示为可执行目标：应用版本为 `21.18.50`、同一规范化标签仅匹配一个节点、节点已启用且对用户可见、节点边界有效且中心点位于根窗口边界内。这样 Profile 能从首页决策出 `CLICK_MINE`。该能力只对百度采集路径启用，高德快照语义保持不变。

### 4.2 Adapter 与节点动作

`BaiduMapAdapter` 继续负责：

- 将百度节点树转换为 `MapUiSnapshot`。
- 将 Profile 的单个动作映射为允许标签。
- 先执行节点点击，必要时请求语义边界手势回退。

节点遍历仍受深度和节点总数限制。手势回退只使用本次遍历中与动作标签匹配的节点，不接受调用方传入任意坐标。

### 4.3 手势分发器

新增窄接口用于提交屏幕点击手势，Android 实现由现有 `AccessibilityService` 持有。Adapter 只接收“点击这个已校验中心点”的能力，不负责服务生命周期。

无障碍服务配置增加 `android:canPerformGestures="true"`。项目最低 API 为 26，满足 `dispatchGesture` 的平台要求。该声明只提供本次受限回退所需的平台能力，不改变服务自动启动、窗口监听或事务恢复逻辑。

### 4.4 Worker

`DualMapCommandWorker` 仍按现有 Profile 循环执行：

```text
窗口根节点
  -> 百度快照
  -> BaiduUiProfile 决策
  -> 百度 Adapter
      -> 节点 ACTION_CLICK
      -> 失败时语义边界校验
      -> 单次手势提交
  -> 延迟后重新识别页面
```

手势提交成功只表示动作已被系统接受，不直接表示打卡成功。Worker 必须等待下一轮页面识别，由 Profile 的新页面或终态证据决定后续行为。

## 5. 安全边界

语义边界手势必须同时满足：

- 仅限百度地图已验证版本 `21.18.50`。
- 动作来自当前 `BaiduUiProfile` 决策。
- 标签来自 `MapUiActionLabels` 的当前百度动作白名单。
- 当前目标窗口根节点非空。
- 匹配节点数量恰好为一个。
- 节点已启用且对用户可见。
- 节点边界宽、高均大于零。
- 节点中心点位于目标根窗口有效边界内。
- 单次动作最多提交一个手势。

任一条件不满足时返回失败并保留结构化证据，不退化到固定坐标、相邻节点、兄弟节点或模糊页面位置。

日志只记录动作、标签、回退类型和校验失败原因，不记录地点、地址或地图经纬度。

## 6. 错误处理

- 节点点击成功：沿用现有成功结果。
- 节点点击不可用且手势校验通过：提交一次手势，记录“语义边界手势已提交”。
- 手势平台拒绝提交：返回失败，由现有重试与超时策略处理。
- 匹配不唯一或边界无效：返回失败并记录关闭回退的具体原因。
- 页面没有发生变化：Profile 循环重新识别，受现有动作次数和总超时限制，不能无限点击。
- 应用版本不匹配：沿用当前版本关闭策略，不执行手势回退。

## 7. 测试与验收

### 7.1 单元测试

先写失败测试，再实现：

- 唯一、启用、可见且位于窗口内的标签节点可以生成中心点。
- 零个匹配节点拒绝手势。
- 多个匹配节点拒绝手势。
- 禁用或不可见节点拒绝手势。
- 空边界、负尺寸和越出窗口边界拒绝手势。
- 节点点击成功时不调用手势回退。
- 百度允许手势回退，高德保持原节点点击行为。
- 手势提交失败时返回失败，不增加虚假的成功状态。

- `:app:testDebugUnitTest`

- `git diff --check`

### 7.3 真机验收

在小米 14 上安装同一构建产物并确认：

1. 无障碍服务为 Enabled、Bound，且 Crashed services 为空。
2. 百度 `21.18.50` 首页能够通过“我的”进入后续页面。
3. 百度按真实页面完成打卡或识别已完成状态。
4. 百度完成后，高德 `16.21.0.2010` 能继续执行并完成对应流程。
5. 整笔事务进入 `COMPLETED`，日志包含 Profile 页面、动作和手势回退结果。
6. 地图窗口切到后台再恢复时继续原任务，不创建错误的单窗口布局。

## 8. 非目标

- 不修改候选地点算法、距离规则、停留规则或去重规则。
- 不修改事务仓储、命令串行、重试次数和分屏创建策略。
- 不为高德地图启用手势回退。
- 不添加第三方依赖。
- 不处理未验证地图版本的通用自动适配。
